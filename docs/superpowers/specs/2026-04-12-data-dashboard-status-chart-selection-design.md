# 数据看板工单状态模块胶囊选中联动设计

## 背景

数据看板页面的“工单状态”模块位于 `miniprogram/pages/data/index.*`。右侧状态胶囊点击后，当前页面已经会更新胶囊选中态，并向左侧饼图发送 `pieSelect` / `pieUnSelect` 动作，但视觉上缺少明确的扇区外扩反馈，导致用户难以感知当前选中项与饼图的对应关系。

## 目标

当用户点击“工单状态”模块右侧任一数据胶囊时，左侧饼图对应扇区需要明显向外扩张。

## 交互规则

1. 点击未选中的状态胶囊：
   对应饼图扇区进入选中态并向外扩张。
2. 再次点击同一个已选中胶囊：
   对应扇区恢复默认状态，不再外扩。
3. 点击另一个胶囊：
   取消此前扇区选中态，并将新对应扇区切换为外扩状态。
4. 数据刷新后：
   仍沿用现有的 `selectedStatusIdx` 状态管理，不新增额外交互入口。

## 实现方案

### 推荐方案

保留现有 `onLegendTap` 的状态切换逻辑，只增强 `miniprogram/utils/chartUtils.js` 中 `getRingChartOption()` 的饼图配置：

- 显式开启饼图扇区可选中能力。
- 为选中态设置外扩距离，使 `pieSelect` 动作产生稳定、可见的扇区外扩效果。

### 不采用的方案

- 只依赖 `emphasis` 强调态：
  更像按压/悬停反馈，不适合表达持续选中。
- 手动重算 `series` 或局部重绘：
  实现成本和维护成本都不必要。

## 影响范围

- `miniprogram/utils/chartUtils.js`
  - 调整环形图 `series` 的选中配置。
- `miniprogram/pages/data/index.js`
  - 原则上不改交互逻辑，除非验证发现当前 `dispatchAction` 需要最小补强。

## 风险与约束

- 项目没有现成自动化测试链路，验证方式以微信开发者工具手动交互验证为主。
- 责任方、趋势、楼层等其他图表不应受到本次变更影响。

## 验证标准

1. 点击任一状态胶囊后，对应扇区明显外扩。
2. 再点同一胶囊后，扇区恢复默认状态。
3. 切换到其他胶囊后，选中态正确转移且不会同时保留多个外扩扇区。
4. 切换日期筛选并重新加载数据后，模块仍可正常交互。
